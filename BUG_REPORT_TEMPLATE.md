# Шаблон баг-репорта

Один дефект — один репорт. Проверка простая: сможет ли автор повторить проблему без вас.

```
Название:  коротко, что сломано
Критерий:  номер из USER_STORIES.md, например 1.4
Где:       устройство и браузер
Шаги:      1. ...
           2. ...
           3. ...
Ожидали:   что должно было произойти по критерию
Получили:  что произошло на самом деле
Важность:  критично / важно / желательно
```

## Как выбрать важность

| Важность | Когда |
|---|---|
| критично | главный сценарий не проходит, данные теряются или портятся |
| важно | мешает работать, но есть обходной путь |
| желательно | косметика, редкий случай, неудобство |

## Пример

```
Название:  Поле «Время» не запоминает выбор после ошибки
Критерий:  1.6
Где:       Android, Chrome
Шаги:      1. Выбрать время 14:00
           2. Оставить имя пустым и нажать «Записаться»
Ожидали:   время остаётся 14:00
Получили:  время сбросилось на 9:00
Важность:  желательно
```

Пример выдуманный: такого дефекта в приложении нет.
