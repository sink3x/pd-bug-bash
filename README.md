# pd-bug-bash

Учебное приложение курса «Проектная деятельность» (ПД ТОП-ИТ), пара 12 «Проверка качества и тестирование».

Это запись студентов на консультации. В приложении **намеренно оставлены дефекты**. У каждой команды свой вариант со своим набором дефектов. Ваша задача — найти их и описать так, чтобы автор смог повторить.

## Задание

1. Откройте https://sink3x.github.io/pd-bug-bash/ и выберите вариант своей команды.
2. Прочитайте [USER_STORIES.md](USER_STORIES.md). Это то, как приложение должно работать.
3. За 10 минут найдите как можно больше расхождений с критериями.
4. Каждый дефект оформите по [шаблону](BUG_REPORT_TEMPLATE.md) в таблице своей команды на доске.

Где искать: пустые значения, слишком длинные значения, границы (последнее место в слоте), повторные нажатия, отмена и обновление страницы, поиск, телефон, неожиданный ввод.

## Как засчитывается

В каждом варианте 8 дефектов на 15 баллов.

| Важность дефекта | Баллы | Сколько в варианте |
|---|---|---|
| критично | 3 | 2 |
| важно | 2 | 3 |
| желательно | 1 | 3 |

- Дефект засчитан, если по репорту его можно повторить: есть шаги, «ожидали» и «получили».
- Один дефект засчитывается команде один раз.
- +2 балла за подтверждённый дефект, которого нет в ключе преподавателя.

## Примеры баг-репортов

Во вкладке [Issues](../../issues) лежат шесть репортов об одном и том же приложении: один хороший и пять с типичными ошибками. Посмотрите, по каким из них автор смог бы исправить дефект.

## Запуск без интернета

Скачайте `index.html` из папки своего варианта (`t1` … `t7`) и откройте в браузере. Зависимостей нет, данные хранятся в `localStorage`.
